    How It Works
    L0 Tendering

    A tender opens at Announcement (M1). Site visit, pre-bid meeting, and pre-bid clarification deadlines are announced, and every department (Operations, Supply Chain, Engineering, Control, Contract, HR, Finance, SHEQ, IT, Risk, Fleet) prepares its risk register, execution plan, and schedule in parallel. The Project Schedule (M3) anchors most department deliverables. Technical offers are circulated once RFQs return (M4), and the tender closes with the Proposal Submitted to client (M5), timed to the Bid Submission Date.

    ↓
    L1 Execution

    Once a tender is awarded, an L1 project starts from the same scope: L1 Announcement (M1), an Early Mobilization Plan (M2), then full Commercial & Technical Handover (M3) from the tendering team to the project team. Post-Bid Clarification (M4) runs until the LOA is received (M5), and the project formally begins execution at Contract Signing (M6) — the point the platform marks the project's Contract Status as Signed. From there, Planning, Cost Control, Supply Chain, Engineering, HSSE and the rest of the departments carry the project through its execution deliverables.

    How the Control System Was Rolled Out
    Standard L0/L1 Rollout
    1. Set up recurring one-on-one meetings with all departments
    2. Shared a workflow diagram of deliverables for departments
    3. Set up a shared folder with a tree matching the deliverables
    4. Implemented a follow-up framework to address delays or lack of response from departments
    International L0/L1 Development
    1. Initiated the development of an International Projects System
    2. Prepared a new version of the L0 and L1 Stages for International Projects
    3. Introduced a new stage called "L-Pre Stage"
    4. Conducted workshops with all involved departments
    5. Gathering feedback and refining the final outputs

    The Control Team's Role
    Setting Up Each Project
    • Conducting workshops and introducing L0/L1 to any new participants/departments (such as assigned PMs in L1 Stage)
    • Preparing all due dates for all deliverables in announcement sheets
    • Distributing all announcements to focal points (new projects / milestones / extensions / closed projects)
    • Setting up the shared folder for any new project and managing its security and access
    • Bridging the gaps and miscommunication between departments
    Running It Day-to-Day
    • Notifying all focal points of any new update/upload on any shared folder via comprehensive daily reporting
    • Tracking & controlling all L0 & L1 deliverables for all projects
    • Routine follow-ups with assigned focal points from each department to facilitate progress, such as internal KOMs
    • Preparing performance reports and updating the live performance dashboard
    • Continuously improving the system through feedback & observations, such as converting some deliverables into Library items

    How a score is calculated – Algihaz's existing rule, carried over as-is

    On-time submission (within a 4-day grace period) = full point. Deliverables not yet due are excluded. Late submissions taper down; anything over 28 days late counts as not submitted.

    On time → 100% 1–7d late → 90% 8–14d → 80% 15–21d → 70% 22–28d → 60% >28d → 0%
